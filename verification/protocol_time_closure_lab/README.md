# 协议时间补全：独立抽象实验

日期：2026-10-10。研究合同：`TIME-CLOSURE-PROPOSED-0.1`。对应[候选草案](../../system_dev/v26/05_time_acceptance_recovery_PROPOSED.md)与[研究简报](../../docs/research/2026-10-10-协议时间补全_研究简报.md)。

本目录只验证有限模型中的时间/事实/观察分离，**不是产品软件、R2全协议实现、真实签名模型或完整39项验收**。

## 做了什么

- `model.py`：T/F/U时间区间、旧样本加可信经过时间界、单操作原子接受、原回执补签上限、候选历史认证与派发门闩的不可变抽象。
- `test_model.py`：27项局部检查，含区间边界、跨秒异步签署、到期/原钥撤销、错事实/请求、缺当前认证/档案/连续性、恢复无副作用、过期不再派发及两个候选共享容量的顺序检查。
- `explore()`：完整遍历声明的有限可达域；5个整数时刻、1操作、2个当前钥代、领取/取消/签署/观察/资格失效/档案丢失事件。此处将原回执寿命缩为3个抽象刻度以覆盖到期，不把3刻度当正式900秒参数。区间边界另用定向检查，不在全部探索路径中枚举。
- `temporal_cases.json`：22项补充协议轨迹与原39项映射，全部`NOT_RUN`；`abstract_checks`只标明可关联的局部模型检查，不代表完整场景通过。

特征轨迹明确复现：原回执100秒冻结、exp=1000，1000秒不能补签；原钥撤销不能补签。新认证机制在显式前提为真时可观察同一原事实，接受/调用增量为0。研究分支Prepare100→Finalize101的相等守卫拒绝，是候选实现的跨秒限制，不是原R2提交后签署的反例。

## 复现

从项目根运行（仅Python标准库）：

```powershell
python -m unittest discover -s verification/protocol_time_closure_lab -p test_model.py -v
python verification/protocol_time_closure_lab/run_all.py
```

运行器向新的`runs/<UTC时间>/`写`tests.txt`与`results.json`，失败退出非零，不覆盖原协议或旧报告。摘要记录实际用例数量、有限状态/转换数量、研究输入散列和局限。

## 成立前提与未覆盖

认证、当前角色范围、历史资格核对、同W账连续性是布尔前提，不是从摘要、字符串、签名或文件存在自动推导。当前可信区间由抽象oracle提供；`advance_sample`只展示有可信总经过时间界时的算术，不能实现网络单程延迟估计、可信时钟或跨重启计时。

未实现：规范字节、Ed25519/公钥严格检查、实际COMMIT/Core/Ref、原始Schema、新Record机器合同、STATUS/Result/Bundle、认证管理入口、完整RequiredDeps、真实数据库/并发/进程崩溃、工具账或三Profile。双候选检查是顺序的受控容量模型，不是数据库并发证据；全局探索只有1操作，不提供跨操作唯一性证明。`calls`把领取和一次抽象调用机会合并，不是观测到的真实工具调用计数；领取到调用窗口及实际结算均未建模。

模型内原子commit是前提；不验证真实持久化和备份防回退。`original_signed`只表示原窗口内签署步骤发生的抽象事件，不能证明真实签名历史。模型中没有公平性、消息延迟或证书链，不能证明长期进展、密钥独立托管或恶意W条件下恢复。

测试通过只支持列明的局部性质。原`system_dev/v26/semantic_cases.json`的39项和66项产品验收保持原状态。
