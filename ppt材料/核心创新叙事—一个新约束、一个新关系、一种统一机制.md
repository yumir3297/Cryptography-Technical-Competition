# 核心创新叙事：一个新约束、一个新关系、一种统一机制

> **一个新约束、一个新关系、一种统一机制。**
>
> 定义需要保护的必要条件，建立这些条件与动作之间的密码学可信关系，并将约束核验、状态更新和执行证据统一纳入动作全生命周期。

2026-11-24 · 国赛 PPT 核心创新叙事基线。依据已合并主线 98e59470ff29bc1e5cf8d7ee1d3fbb039c567f22。排序原则：优先展示现有调研方案尚未明确采用同样构造、且有实验证据支持的设计；其次突出密码学性质运用与协议组合的巧妙程度。不将成熟原语或通用工程组件本身称为创新。

## 一、总纲：三项贡献不是三种独立功能

| 顺序 | 核心抽象 | 回答的问题 | 展示重点 |
|---|---|---|---|
| 01 一个新约束 | 目标必要资源的前瞻性保护 | 我们额外保护了什么？ | 研究差异化 |
| 02 一个新关系 | 多源异构信息的密码学关系约束 | 如何建立可信性？ | 密码学设计思想 |
| 03 一种统一机制 | 状态约束与密码学证据的原子耦合 | 如何真正落实安全约束？ | 协议深度与实验效果 |

递进关系：**定义安全约束 → 构造可验证关系 → 原子化落实约束与证据**。

前置问题剖析：Agent 概率性、自主性、动态连续性和外部作用性带来授权边界、连续状态安全及跨阶段一致性三类风险。密码学可验证性是贯穿三类问题的共同基础，而不是额外拼接的功能。传统程序也可能存在这些风险；本项目聚焦智能体自主决策放大的高后果操作风险。

## 二、一个新约束：目标必要资源的前瞻性保护

**Goal-aware Necessary Resource Preservation**

### PPT 主标题与正文

**单步合法，不代表后续必要条件仍然成立。**

常规资源上界约束限制当前动作超支；本协议进一步保护尚未完成的必要事项所需资源，防止局部合法的连续动作侵占后续必要资源。

```text
Spent + Reserved + CandidateCost + RemainingGoalFloor <= Capacity
```

其中 RemainingGoalFloor 为当前候选动作匹配后剩余必要事项的资源下限，依据经认证的约束和账本计算，不是 Agent 自报预算或未来规划结果。

### 设计巧妙性

- C 签名发布 GOAL_FLOOR，绑定任务、策略等依赖版本与引用。
- W 以冻结 Action 的 selector 匹配规则，依据可信 plan.amount 确定成本；Agent 无权自行挑选、删除或修改适用约束。
- 必要事项随 OPEN/PENDING/DONE/BLOCKED 状态演化；未确认效果不能等同于完成。
- 核验和资源预留、义务登记、COMMIT 写入在同一接受事务内完成。
- 新 epoch 保持义务集合；停用仍有 PENDING 链接的 Goal 时阻断新接受。

### 建议图示

用同一资源条比较普通上限与必要资源下限：总容量 100，已消耗 50，新动作 30，后续必要资源 35。普通上限允许 80≤100；新约束拒绝 115>100。此为解释例，不是实测数据。

### 实验支撑

E1：20 条真实 CommonW 配对长序列（5 种固定模板），112 个候选动作位置，20 个对照允许而 enforce 拒绝的差分位置，独立 Oracle mismatch 0；另有 10,000 条独立参考模型序列。IND/PAY/MED 与事件响应均有相关验证（事件响应复用 IND wire）。

差异化口径：AADP 已涉及累积预算与原子预留，Tether 已涉及有状态安全不变量。现有调研未确认其采用与本协议相同的 C 认证必要事项下界、冻结动作匹配、原子接受及证据绑定的具体组合。不得宣称资源预留、前瞻约束或不变量思想本身为首创，也不声称已有真实竞品同测。协议只维护已定义的必要资源条件，不保证目标可达或最终成功。

## 三、一个新关系：多源异构信息的密码学关系约束

**Cryptographic Relational Binding**

### PPT 主标题与正文

**每份信息都真实，不代表它们的组合合法。**

本协议将签名认证、哈希承诺、规范化对象及必要依赖重算结合，把任务、策略、身份、业务状态、动作、批准与执行证据组织为可验证的关系结构。

### 设计巧妙性

- ActionHash 承诺完整冻结动作，而非仅承诺自然语言意图或工具名称。
- Ed25519 认证登记主体及相应对象；域分离、规范编码及引用绑定限制跨对象、跨场景混用。
- W 独立推导 Basis、Assessment、required_reviews 和 RequiredDeps，验证提交的承重依赖与可信推导集合精确一致，而非仅验证收到的签名。
- 各阶段验证对象引用、用途、范围、角色、版本及当前性；不能用合法签名替代业务关系检查。

概念表达：

```text
D_required = Derive(frozen_action, authenticated_context)
D_submitted == D_required
```

以上为抽象表达，实际依赖及编码以协议规范为准。

### 建议图示

四份单独签名合法但来源于不同任务、版本或动作的对象 → 组合关系非法；再展示任务/策略/状态与 ActionHash、Refs、多方签署和 W 独立重算之间的有向依赖结构。

### 实验支撑

E3：15/15 定向篡改或重放拒绝，合法包 PASS；另有合法签名但容量不一致、跨 Profile/资源借用、旧依赖版本及非法删除 obligation 的关系负例。

差异化口径：对象签名、哈希引用、多方批准和审计证据并非新密码学原语。AP2 已有密码学授权链，其他动作授权协议也有相关技术。重点在必要依赖的可信重算及跨阶段业务语义一致性的具体组合。签名真实性不自动证明外部事实真实性、依赖完整性或业务正确性，须依赖可信规则与受信发布者。

## 四、一种统一机制：状态约束与密码学证据的原子耦合

**Cryptographically Bound Atomic Acceptance**

### PPT 主标题与正文

**安全判断必须与其实际接受的状态变更绑定。**

在 W 的同一事务中完成当前授权及资源条件复核、资源预留、意图与义务登记、COMMIT 和冻结接受事实；随后由 X 签署包含 commit_record_ref 的 Acceptance，连接唯一执行资格、工具终局和结算证据。

### 设计巧妙性

```text
W transaction:
  Verify + Reserve + Commit
  → COMMIT / RecordRef
  → X-signed Acceptance
  → unique attempt / EXEC-0
  → authenticated tool final fact
  → once-only settlement
```

- W 的事务控制避免两个动作基于相同旧状态同时占用同一资源。
- COMMIT.value.goal 保存 goal_refs、deps、matched、资源计算及 state_ref/check_ref；X 签名间接绑定完整见证。
- 先固定 COMMIT 并求 RecordRef，再固定 Acceptance Core，避免摘要循环；回执失败只恢复原冻结对象，不能换动作或再授予执行资格。
- UNKNOWN 保留占用并查询原 attempt，不把超时解释为无效果，不自动重派或重复结算。
- 独立离线验证器在外部固定信任根及证据包条件下重算签名、引用、GoalFloor 算术和终局关系；无须读取 W 数据库。验证器复算与独立参考模型实验应区分，前者复用部分核心求值代码。

### 实验支撑

- E2：40/40 真实 W 并发历史存在合法串行解释；另有 10,000 条独立参考模型历史及 240,000 次转移。
- E3：15/15 定向篡改拒绝（与创新二证据重叠，不相加）。
- E4：3/3 新增真实子进程崩溃边界通过。
- E7：4,363 个有限模型状态、67,746 次转移、所检查不变量违反 0。
- E6：真实 accept 每模式 40 次，p50 1324.9 / 1338.4 ms，增幅约 1%；证据包约 +1.6%。探索性样本，不宣称稳定尾延迟或吞吐优势。

差异化口径：原子事务、签名回执、幂等执行均有先例。本协议的贡献是将 C 认证的必要资源条件、W 原子接受及跨阶段密码学见证耦合成统一机制。X 回执在 W 接受事务之后签署，不意味着事务和签名是同一物理原子操作；协议接受不等于任意外部设备的原子效果，也不能由签名独立证明账本的现实真实性。

## 五、PPT 与答辩统一口径

### 推荐三页核心创新

| 顺序 | 标题 | 核心视觉 | 结论 |
|---|---|---|---|
| 1 | 一个新约束 | 资源条与连续动作反例 | 保护后续必要资源条件 |
| 2 | 一个新关系 | 多源证据依赖图 | 从单对象真实性到关系一致性 |
| 3 | 一种统一机制 | W 事务与 COMMIT/X/工具证据流程 | 将安全约束落实到动作全生命周期 |

整体架构页之后按以上顺序讲述，不按 C、E、G、W 等角色逐个介绍创新。UNKNOWN 恢复融入第三项，跨场景表达放在实验与应用展示。Ed25519、SHA-256、nonce、持钥证明、T/F/U、SQLite 等作为技术基础，不独立列为原创贡献。

### 推荐总述（可直接用作演讲稿）

针对智能体自主决策产生的高后果动作安全风险，本协议形成了一个新约束、一个新关系和一种统一机制：首先，通过目标必要资源下限保护连续动作中的必要条件；其次，通过数字签名、哈希承诺与依赖关系重算，建立多源安全信息之间的密码学可验证关系；最后，将约束核验、资源状态变更与接受事实进行原子化耦合，并通过签名回执连接后续执行与终局证据。三项设计共同构成从动作授权到执行结算的可验证安全生命周期。

### 审计边界

“新”指本作品具体研究构造与组合贡献，并非已证明学界首创。当前结论为 CONDITIONAL_READY；GoalFloor 仅在 enforce 模式下提供强制保障，默认 off、shadow 不阻断。正式 39 项为 2 PASS / 22 PARTIAL / 15 NOT_RUN；Linux/WSL 526 项单次运行有 1 failure / 3 errors，隔离复跑通过但尚无单次全绿。不承诺跨 Profile 原子性、证据当期性、外部现实状态真实性或真实设备效果。真实 W 指实际运行本项目 CommonW 签名与事务路径，场景效果为模拟，不等于生产环境实测。各实验统计可能重叠，不应相加或将模型样本冒充真实 W 样本。
