# PPT 第二页：现有方案如何解决智能体动作安全问题

整理日期：2026-11-24。承接《研究问题与权威文献引用》。本页比较公开研究的机制与范围，不是已完成的性能对照实验。

## 一、四类代表性方案

| 方案 | 技术机制 | 主要保护对象 | 研究范围 |
|---|---|---|---|
| CaMeL [1] | 特权与隔离 LLM、控制流/数据流分离、能力检查 | 不可信数据影响下的工具使用 | 提示注入与信息流 |
| Google AP2 [2] | 签名授权凭证，将用户授权绑定到交易和支付 | 支付授权 | 智能体商务支付 |
| Tether [3] | 临时隔离沙箱、系统调用语义推断、有状态策略、Lean 4 验证 | 多步骤动作及其可观察副作用 | 运行时安全不变量 |
| AADP [4] | 两阶段决定与报告、可变授权状态、预算预留、幂等与证据 | 动态状态下的逐动作授权 | 通用动作决策协议 |
| ZJJ-CORE | 签名与哈希引用、必要资源下限、原子接受 | 从提案到最终接受的动作证据与状态关联 | 本项目设计定位，实际保证以规范和实验为准 |

## 二、PPT 四象限机制图（绘制建议）

- CaMeL：可信用户任务 → 特权控制流程；外部数据 → 隔离处理；两路进入能力检查 → 工具调用。重点是隔离数据与控制，不是验证全部业务结果。
- AP2：用户意图 → 签名交易授权 → 支付授权。注意版本差异：早期 Cart Mandate，在 v0.2 中由 Checkout Mandate 替代。
- Tether：动作 → 沙箱观察 → 提取语义 → 有状态策略判断 → 允许或拒绝。跨动作状态支持安全不变量。
- AADP：动作申请 → PDP 决定及预算预留 → PEP 执行 → 报告并结算预留。不能简化为无状态权限检查。

## 三、项目研究切入点

1. 约束对象：已定义且可验证的后续必要资源下限，而非替 Agent 规划任务或证明目标可达。
2. 证据组织：将任务、策略、状态、动作与执行证据以签名、哈希承诺和引用绑定。
3. 接受语义：区分授权和最终接受，在明确的信任假设下完成原子状态更新及独立复核。

以上为项目拟重点展示的组合，不宣称其他系统完全不具备这些能力。尤其 AADP 已具备累积预算、原子预留、幂等与可复核证据；Tether 已具备全局安全不变量。必须进一步核对必要资源下限与预算预留是否语义等价、证据验证边界及并发接受语义。尚未对照验证的能力不得标为竞品不支持。

## 四、建议答辩叙事

现有方案分别从信息流隔离、签名交易授权、有状态运行时策略及逐动作决策协议控制智能体行为。我们聚焦在高后果业务动作中，将必要资源条件与跨阶段密码学证据关联纳入统一的动作授权和原子接受流程。
