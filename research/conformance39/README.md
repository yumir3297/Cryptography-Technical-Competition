# ZJJ-CORE-2.6-R2 | 39-case executable evidence gate (Phase 9)

**Purpose:** turn the upstream 39-item *semantic specification* into 39 separately auditable, executable evidence units. **It does not equate a subset test with a completed full official conformance case.** Work remains scoped to cryptographic protocol modeling, not physical attacks, medical decisions, or real transfers.

## Quick start

```bash
# Unzip package directly into your repository root containing system_dev/v26/.
python -m unittest research.conformance39.test_runner_integrity research.conformance39.test_enrollment_lab research.conformance39.test_industrial_advance_lab -v
python -m research.conformance39.run39 --upstream-root .
# One case (for manual adjudication):
python -m research.conformance39.run39 --upstream-root . --case-id PAY-02
```

Files generated by the all-case runner: `research/conformance39/official39_evidence_report.json`. A human-readable summary and CSV for this release accompany it. Every case has specific test names, actual run result, full requirements still missing, and a result that explicitly says official full conformance is **not established**.

## What the numbers mean

- `PARTIAL_WITNESSES_PASS`: actual named unittest methods executed and passed. It **is not** `PASS` against the original full semantic case.
- `LOCAL_WITNESS_FAILED`: at least one witness genuinely failed, errored, skipped, or did not execute.
- `BLOCKED_NO_EXECUTABLE_WITNESS`: no witness exists for that requirement.
- `HARNESS_ERROR`: a declared witness cannot be resolved; never count as PASS.
- `official_full_conformance=NOT_ESTABLISHED`: deliberately conservative. The official manifest `semantic_cases.json` is **not rewritten**.

The original case manifest must match the pinned Git blob SHA-1 `b0bc9dbeedac135f6520b5e93729f63686d97bb4`. Official PAY/IND/MED schemas likewise must match pinned Git blobs. If the package is run **outside the cloned upstream repository**, missing original IND/MED schemas and manifest are clearly marked, not substituted with handwritten approximations. When both original IND/MED schemas exist, the runner calls the prior Phase 8 emitted-record structural check, and preserves its result. Custom schema annotations such as `x-zjj-order` are additional semantic obligations beyond JSON Schema Draft 2020-12.

## New case coverage from this phase

### CORE-19: enrollment PoP local executor

`enrollment_lab.py` / `test_enrollment_lab.py` implement the exact `ZJJ-ENROLL-v1` signature domain, full pending tuple binding, purpose and scope, a 60-second proof lifetime, nonce replay resistance, root-generation pin, SQLite atomic KEY_GRANT publication, and idempotent byte-identical replay. These checks use real Ed25519 signatures and preserve `enrollment_ref` and a local audit row. **Not implemented:** production C authenticated issuer, external enrollment service, independent identity verification, certified approval of applicant facts, and full role governance. The testbed is not a substitute for real authentication.

### IND-04: two-cycle industrial synthetic transition

`industrial_advance_lab.py` / `test_industrial_advance_lab.py` implement a local authenticated-signed FinalFact, SQLite atomic settlement with reservation and flight guard, cycle-1 `INSPECT → AWAITING_REINSPECT → READY/REINSPECT` C-authorized simulation, cycle-2 `INSPECT → MANUAL_HOLD`, and reject unknown/failed/forged or duplicate finals. The second cycle completes a **second independent signed Issue → Challenge → Commit** path in the scene authority. **Not implemented:** independent C certificate on the advance command, external certified TOOL_TRUST and provable physical tool ledger continuity. The fixture `controller_approved=True` is an explicit lab trust assumption.

## Why the full 39 are not yet PASSED

Many official rows require more than one isolated behavior: reference graph closure, current C/E publication evidence, exact scopes and epochs, signed refusal outcomes, semantics under an authoritative W transaction, signed Status/Result matrices, crash / unknown recovery, external tool trust, and transport-profile isolation. The local fixtures are not independently authenticated complete production systems. The previous `FinalW.claim_bound` still has a known post-accept revocation gap; Phase 7 supplied an experimental `GuardedFinalW`, but this is not fully wired into every executor. Calling that row full PASS would misrepresent the threat model.

For full certification of a row, assemble a standalone input fixture with all official typed signed objects, reproducible C/E/W setup, expected and actual T/F/U, immutable evidence IDs, verified snapshots of all state and side effects, a replay script, complete negative branches and a reviewer adjudication. After all these have been **executed**, update the separately maintained official status with its **specific** evidence pointers. Do not bulk replace `NOT_RUN` with `PASS`.
