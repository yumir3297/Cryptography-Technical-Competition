# Phase17 — IND 工业可信决策最小闭环

**实现目标：让一条工业质检分流建议从 E 签署的合成检测证据进入 W，经不同角色批准，再到外部 X 接受、W 授权派发、工具网关记录模拟效果、工具签名回执、W 一次结算，最后由只读审计程序交叉核对。**

这是**比赛参赛用可信协议运行原型**；不等于真实工业控制器或生产安全认证。Phase16 的工具去重与失败恢复逻辑全部复用，不另造协议。PAY/MED 不在本阶段开发范围。

## 运行和审计路径

```text
[Provisioner] 生成每次运行不同的 C/H/G/X/U/V/E/W-tool/Tool Ed25519 密钥
          ↓ 仅将公钥登记给 W（本地历史注册过程仍是实验夹具）
[E 子进程] 签署第二份合成检测数据
          ↓
[W] 先拒绝伪造 E 签名，再验证合法 E SOURCE 和现行授权，更新状态
          ↓
[W] 从证据重建 assessment/basis/deps，规划原始 IND 操作
          ↓
[U → H → G → H → X → H] 依次分别运行各签名子进程
          ↓
[C] 签发 PREPARE 时间 → [W] 无副作用准备
          ↓
[X] 签发 Acceptance → [W] 拒绝错误 X 签名 → 接受并原子预留
          ↓
[C] 签发可信工具证书和 DISPATCH 时钟
          ↓
[W] 依据冻结状态唯一 Claim，持久化与 COMMIT 绑定的签名派发令牌
          ↓
[工具网关] 拒绝错误的 W 签名；原子写入一次模拟效果记录
          ↓  工具进程在 COMMIT 后异常退出（没有回复）
[工具新进程] 通过相同令牌找到原始记录，不增加效果次数
          ↓
[工具] 签发 TOOL_FINAL → [C] 签发 SETTLE 时间
          ↓
[W] 验证工具原始账本与签名，一次结算并释放预留，禁止二次派发
          ↓
[只读审计] 验证签名/COMMIT/SQLite 事务/工具状态/唯一事实
```

## 相比 Phase16，新闭合的具体缺口

1. **新增 E 真实独立调用签名**：调用者不能自行修改检测记录后交给 W；W 验证 E 的 SOURCE 签名及 C 授予的 SOURCE 凭证，并以状态变化绑定证据和决策。
2. **各角色分别签署**：H/G/U/X 的许可、挑战、确认不再由统一的 `prepare_approved` 一次性代签；每一类签名在对应子进程内调用，其私钥不传给 W。每次运行生成不同的密钥。
3. **可观察的负向证据**：篡改 E、X、W 任一个关键签名都会在进入下一步前被拒绝，且不能留下已接受/已执行的副作用。
4. **可恢复的唯一模拟效果**：工具进程在持久化成功后退出，重试必须返回同一份原始事实，W 不得再次派发。
5. **不覆盖旧版研究**：对 Phase8 fixture 的临时适配完全在 Phase17 中完成；原版 v2.6 Schema、39 项和历史源代码哈希均原样保留。

## 最小闭环判据

| 条件 | 实验判据 |
| --- | --- |
| E、C、X、W 不共用同一签名钥匙 | 至少 9 个不同的临时 Ed25519 公钥 |
| W 无 C/E/X 私钥 | W 构造器只接收公钥、公用权限数据 |
| E 源数据真实来源的实验模拟 | 当前状态绑定 E 签名；篡改 E 被拒绝 |
| 提交前否决 | 错误 X 签名拒绝，不占用配额 |
| 已授权操作交付 | 唯一 W CLAIM + 专用签名令牌，工具验证 |
| 故障之后不会“因为没回执就重复发起新动作” | 硬退出后同令牌恢复原始模拟事实 |
| 完整审计 | ACCEPT=1，DISPATCH=1，SETTLED=1，模拟效果=1 |
| 原版兼容 | 4 份原始合同/语义清单 hash 不变，39 项不得假报 PASS |

## 仍明确没有闭合的真实部署边界

- **独立密钥托管**：本阶段部署准备器仍能访问所有密钥，角色子进程运行于同一 CI OS 账户，仅属于“公私钥边界正确与签署接口拆分”验证，**不是**真实的 HSM/KMS/独立服务账号隔离。
- **物理事实**：工具记录的是数据库模拟结果；这并不能证明物理设备恰好执行一次。实际投产应要求工业网关提供硬件可审计执行 ID、设备端幂等屏障、安全停机机制。
- **跨系统信道**：本地文件交接，不是认证的 mTLS 消息通道，也没有故障注入覆盖所有网络异常。
- **时间一致性**：仍由实验性 C 时钟签 PREPARE/FINALIZE 的**同一时刻**，尚未完成容许真实时延的协议语义。
- **官方符合性**：原始官方 39 项仍按完整义务逐项评估，0 FULL PASS；这个最小闭环是**工业候选证据**，不是对正式通过的替代。

下一阶段不扩展三种场景。只需要选择 **（1）真正隔离的 C/E/X 服务密钥；（2）容许非零延时的提交语义；（3）设备侧可信执行回执** 三项逐一收敛到 IND 工业部署模型即可。
