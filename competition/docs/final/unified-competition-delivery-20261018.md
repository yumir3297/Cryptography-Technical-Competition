## 1. 交付范围与展示安排

**工业为全流程主展示；工业、付款、医疗三个场景的本地 CLI 为补充演示。**

| 入口 | 展示内容 | 使用范围 |
|---|---|---|
| 工业受控服务 | 认证候选、可信字段构造、ID 分配、多角色模拟批准签署、提交、短证明更新、接受、冻结回执、内部 worker 执行、查询、结算和重启恢复 | 受信单机、回环 HTTP、可选 MCP stdio、工业签名模拟工具 |
| 三场景本地 CLI | 工业、付款、医疗共用核心的动作绑定、批准链、接受、模拟执行、状态和审计投影 | 独立的可信本地演示安装；LocalSigner 仅用于模拟身份 |

全流程中的业务效果是工具数据库中的模拟事实；批准由受控模拟角色生成有效签名，不代表已采集真人审批。PAY/MED 不声明具备工业新版公开提案、提交和恢复服务。

统一的是代码交付、协议核心、展示范围和集成基线。两种入口继续隔离；本地 CLI 不连接工业公开服务的运行账，模拟签名器不注册为 HTTP/MCP 工具。

## 2. 如何解决最初开发问题

| 问题 | 最终实现 |
|---|---|
| 六个字段缺少可信来源 | IND 三字段 CandidateProposal 由 Resolver 依据认证 Task、Policy、KEY/ROLE 和工具登记构造原十字段 Action；调用方不自定权威身份 |
| operation_id 分配与哈希顺序 | W 所属事务内生成 B16，检查请求账及既有操作冲突，持久映射后再构造 ActionHash 和审批材料 |
| 重试、超时、重新签署冲突 | 单一 RequestStore；固定动作、依据与批准，仅在未接受且原授权有效时更新短证明；CAS、历史标识和 W 事务检查拒绝旧包与旧 ticket |
| Agent/MCP/H/W 责任混淆 | HTTP/MCP 承载十项白名单；传输 token 不代替 H 身份；批准、回执及 worker 职责分离，公开服务强制绑定 RequestBoundW |
| 长连接与重启恢复 | 本机 HTTP 短连接和认证恢复原请求/COMMIT/attempt；已消费执行资格只查询原尝试，不重发 |
| 多份草稿与集成基线混乱 | 一个直接面向稳定比赛分支的统一提交；旧草稿标记被替代，不删除历史分支 |

## 3. 对其他部分的影响与边界

融合基线的运行源码、测试、Schema、ActionHash、签名域、DENY、时间阈值、冻结 Core 和 EXEC 规则在本轮保持不变。本轮仅整理文档和增加最终验收记录；不引入第二套分配账或公开签名入口。

保证依赖受信 OS、私钥、固定登记、持久账、唯一执行入口和可信经过时长。演示期间保持宿主清醒；防空闲休眠不覆盖人工休眠/强制暂停，不能宣称任意暂停后仍能保证绝对到期。CLOCK_UNKNOWN 保持失败关闭。领取后新增撤销不保证阻止原派发；未知效果不因超时释放或重派。

原 R2 的完整 39 项符合性、实体工业设备/真实支付/临床效果、生产密钥托管和跨机部署均不在当前展示结论内。协议差异见 [R2 对照](r2-application-mapping.md)，安全前提见[安全边界](security-boundaries.md)。

## 4. 开发接入与复现

工业按[部署步骤](../../deployment/README.md)在全新私有模拟目录连续执行 provision 与 acceptance。实际服务只开放工业白名单，worker 在内部推进执行与结算。旧安装恢复使用原配置与持久账，不重新初始化。

工业入口、角色和方法见[统一服务契约](unified-operation-contract.md)；字段与恢复细节见[工业交付说明](ind-complete-delivery-20261018.md)。融合过程保留在[历史融合记录](fusion-experiment-20261018.md)。
