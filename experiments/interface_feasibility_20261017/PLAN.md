# 通用接口隔离可行性实验计划（已授权 E1–E4）

问题：能否只增加受信应用适配层，保留当前竞赛协议全部核心语义？
这是隔离可行性探针，代码只作实验，不是正式接口上线。

基线：competition/zjj-core-final-20261010，固定 cc4e36b4e302fcdc53cc809a012c77d8464182af。

1. 在独立克隆和 experiment 分支核实基线，运行 competition/tests。
2. 先定义实验验收测试，观察“缺少适配器”的失败，再实现 adapter.py。
3. adapter.py：服务端固定 IND Task；H 签名认证提案；校验 Task/Policy/KEY/ROLE/tool 证书；构造十字段 Action；新表记录 B16 ID 与稳定请求映射。
4. lab.py：仅受信模拟端根据新 Action 构造 Assessment/Basis，通过既有 broker 完成显式模拟批准和签署。Agent 输入面仅三个业务字段，无签署或执行能力。
5. 先持久化完整 op，再调用原 W prepare/accept；freeze 写入后不能替换请求，恢复仅重放原 op。
6. 验证完整工业执行、授权拒绝、摘要冲突、并发分配、进程退出恢复、工具丢应答、未知终局。
7. 保存每项结果、公开 W/工具证据、准确命令、失败记录和限制；检查核心及原证据逐字节不变；仅发布隔离实验分支。

重点审查：非法字段与类型、认证与任务错绑、KEY/ROLE 撤销、同请求不同业务意图、已签完整请求重新生成、W 提交与回执间崩溃、工具未知终局不释放资源。
